# Android encrypted group actions — progress

Direct-message wire/state/UI checks are qualified and pushed at `7d4a684`. Inspection found the legacy Android group client accepts server `edit_of` as a fallback to decrypted references and uses server replacement hints to hide messages. It also prepares a new encrypted send after ambiguous loss and ignores deletion response seq sets. These boundaries are being corrected before exposing group action controls.

AST/impact inspection: `GroupModels.kt`, `GroupClient.kt`, `GroupStore.kt`; no usable Kotlin dependency edges were returned. Exact call sites and the established Apple `GroupActions`/pending-send implementation supply the contract; the runtime and existing real MLS library remain the qualification source.

## Full regression caught avatar capability timing

The first integrated run passed all 143 JVM cases and the new group cases, but the 72-case UI run had one failure (three expected opt-in skips): the existing missed-call/avatar test timed out waiting for a profile photo. It passes alone. Inspection found Avatar keyed its lookup effect only by peer; when a visible face appeared before `AvatarStore.enable(true)`, the ignored lookup never retried because an empty picture map did not emit a change. A new deterministic UI case mounts the face before enabling the store and reproduces the failure in five seconds on the old code. Evidence: `android-message-groups-full-platform.log`, `android-message-groups-safety-focused.log`, `android-avatar-availability-before-fix.log`.

The fix exposes capability availability as a StateFlow and keys the avatar effect on both peer and availability. The local draft provided the flow scaffold but assigned `true` instead of `on`; that line was corrected before use. New and existing focused cases, full regression and tablet checks must pass before this checkpoint is qualified. This adds one UI regression case (73 total expected, including the same three opt-in skips).
