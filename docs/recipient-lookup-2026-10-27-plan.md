# Canonical recipient lookup for native delivery

Windows protected recovery now freezes its sender, recipient and exact wire request before POST. Users type handles; the server must resolve them without sending a message or changing contacts/threads. This is a prerequisite for connecting native edit/reply and restart recovery to the composer, within the existing native round-two work. Nests/Products remain planning only and native stores remain held.

1. Add a bounded authenticated `POST /v1/recipients/resolve` route with an optional acting-inbox selector and one recipient. Reuse `acting_identity` and the exact `resolve_recipient` used by delivery, including closed-organization masking. Return only canonical sender/recipient and the recipient's current handle. Never return capability tokens, keys, policy or private profile data; do not modify messages, contacts, threads or admission.
2. Gate the route behind `recipient_lookup`, advertise it in capabilities, and use the existing bounded per-mailbox rate limiter. Keep feature-off/unknown, malformed, unauthenticated, foreign-inbox and unresolved results explicit. Resolve a canonical address as well as a handle; do not make the client depend on avatar or group features.
3. Document the route in the OpenAPI and message-action contracts. Clients must bind lookup to the original accepted account, reviewed inbox/conversation/draft and returned canonical sender, then persist the canonical recipient and original request. A retry never resolves a handle again. Current permission, admission, references and expiry are still enforced by send.
4. Inspect exact-root symbols/impact/DAG first, then prove the route with actual loopback HTTP: flag/capabilities, selector ownership, root/named handles and canonical keys, invalid/missing inputs, closed-org masking, rate limits and absence of message/thread/contact side effects. Use synthetic accounts only. Run the postbox tests, fmt/clippy and OpenAPI checks; qualify CI before merge/deploy.
5. Deploy only the qualified server change using the existing server workflow and server-side backup policy, enable its rollout flag, then connect the native composer using the protected-recovery scope. Do not copy production databases to this Mac or expose credentials. Record all source, validation, deployment and remaining gates separately.
