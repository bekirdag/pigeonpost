# Android authorization scope — progress

Created isolated worktree/branch from `5a7ec71` while the parent Android candidate completes full qualification. Inspected Session's existing generation/mutex flow, TokenProvider/PostboxClient and KeystoreGroupStorage. The existing boolean-ready collector cannot distinguish accepted grants with the same readiness state, and the shared token provider can be called by a retired store; new typed contexts must address both before enterprise step-up is exposed. Group storage already serializes IO through one Mutex, which is the correct boundary for scope checks.

## Core lease foundation

Added parent/child authorization leases and a scoped token provider with explicit expected-grant renewal/invalidation hooks. The first focused run passed six of seven tests and caught a lock-order timing issue: already-retired work waited for an admitted writer instead of rejecting immediately, causing that writer to time out in the test. `withActive` now checks retirement before acquiring locks and again under the lock. The same writer/quiescence test must pass alongside suspended-token and grant-replacement checks. This remains unconnected to Session/network/storage, so it is not yet the full authorization boundary. Local test draft: the first tree-retirement case was usable; a second case omitted retirement and was rejected/refined against the actual contract.

The guard/quiescence correction passed all seven focused cases and the 150-case integrated core suite/app debug compilation. An additional nullable-return test then caught an Elvis fallback invoking guarded work twice when it returned null. Replacing that fallback with an explicit parent branch fixes the generic contract before it is used for nullable vault reads. The final qualification includes eight lease cases (151 total JVM cases) and app debug compilation; see `android-authorization-lease-platform-final.log`. This commit is only the tested core primitive; Session, mailbox client/storage scoping and lifecycle reset integration are still required.
