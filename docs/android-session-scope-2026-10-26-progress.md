## Accepted grants, mailbox actors and actual storage

- Session now restores/accepts a fresh authorization identity, preserves it for token refresh and terms changes, and checks expected grants inside its mutex for token renewal/invalidation/logout. Accepted replacement retires the old root and waits for admitted synchronous work before publishing a new one. Delayed sign-out targets its original grant; native call tasks use the same store scope. OAuth/PKCE/nonce checks remain in place.
- Store jobs carry an immutable authorization context from launch. Reset retires it before clearing caches/composers. The ready collector includes the accepted authorization ID. Push cleanup preserves the local display gate and coordinates old token deletion with later registration; the worker captures its original accepted grant.
- GroupStore retires its mailbox child before teardown, including initialization. All group metadata/files/calls use that captured client transport. Crypto/device operations check the lease while they execute, and KeystoreGroupStorage checks inside its serialized IO guard for load/save/remove. No coroutine suspension is inside a synchronous authorization guard. Late enrollment cannot overwrite a replacement device record.
