# Windows direct-message delivery custody

Continue [message actions](windows-message-actions-2026-10-27-plan.md) in a child of UI source `41405b0`. The prior UI/wire CI sources remain unchanged. Native stores remain held, and Apple App Review requires the owner's Claude review. This work adds no hosted agents or Products implementation.

1. Establish a stable storage-owner hint only from the app's existing fixed token exchange, following the Android trusted-exchange boundary. This is not a stand-alone JWT signature verifier or server permission. Require the expected issuer/client and a bounded nonempty subject; expose only a redacted identity/fingerprint. Ordinary renewal must not replace an already known principal or persist the replacement refresh token. Existing context-free test providers remain unknown-owner stand-ins.
2. Bind recovery access to the exact accepted account, postbox origin and a canonical mailbox freshly authorized by the server. A parsed owner hint alone never authorizes reading or retrying stored work. Reauthentication resets volatile state; a different owner/origin cannot see another partition's attempts. Unknown-owner clients cannot expose durable retry UI.
3. Add protected, atomic attempt storage using the existing Windows DPAPI/state-protector mechanism. Resolve and freeze the recipient's canonical address before preparing the first POST; an uncertain retry must never resolve a potentially transferred handle again. Store the complete immutable wire bytes/reference before POST, with owner/origin/mailbox/draft context and bounded validation. Retire stale actors before final reads/writes/removal, refuse unreadable or mismatched state, and preserve the prior complete file on interrupted writes. Never store tokens or plaintext request files. A different unresolved delivery intent must not overwrite an attempt.
4. Integrate send/reply/edit custody, preserved drafts and explicit check/retry/discard actions. A retry uses the exact original payload and reference only after the account, mailbox and reviewed intent are confirmed again. No automatic non-idempotent replay. Receipt confirmation may update its original draft only if that revision is still owned. Handle already committed sends/edits, lost responses, cleanup failures, app restarts, attachments and expired targets explicitly.
5. Qualify identity changes/vault failures and cross-account recovery with controlled fixtures; prove atomic protected storage and interrupted/cancelled writes; run actual Rust-postbox response-loss/restart cases, Core/MLS tests and Release build. Extend the actual WinUI smoke test with explicit recovery and composer state. Merge only after native CI, then continue authenticated group actions, calendar and enterprise screens.

Track evidence and open gates in [the progress ledger](windows-send-custody-2026-10-27-progress.md). All automated operations use synthetic local fixtures; no production accounts, messages, OAuth requests, credentials or database copies.
