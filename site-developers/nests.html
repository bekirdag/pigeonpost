Build a Nest

A marketplace Nest app is code you publish and Pigeonpost runs for buyers. Pigeonpost builds it from your source tree, reviews it, and has named staff approve it before anyone can run it. Each buyer gets their own isolated worker, and the app's only network peer is the model broker: it reaches no internet, no Pigeonpost service and no other Nest.

You can build, test and run an app on your own machine today with the local kit: pigeonpost nest init starts one from a template and pigeonpost nest run runs it against a mock broker. Start with the quick start.

Concepts#

TermWhat it is
NestA hosted Pigeonpost agent with its own workspace, run by Pigeonpost in an isolated sandbox
PublisherA Pigeonpost account or organization certified by Pigeonpost staff to publish. Org publishers have the team roles publisher_admin (acts, publishes with step-up) and publisher_finance (reads only)
ReleaseOne immutable build of your source tree at one version, made by Pigeonpost from source (never from an uploaded image), with an SBOM and one release digest. Named Pigeonpost staff approve every release a buyer can run
OperationA named, versioned function a release offers, such as docs.ask version 1.0. Buyers invoke operations
JobOne invocation of one operation. Delivered at least once; the job id is the dedupe key, so a job may arrive twice and must not act twice
ListingHow a release is offered in the Services tab catalog of the Pigeonpost apps: an address, a visibility and terms. One listing address serves many buyers
InstallationA buyer's installed listing. It pins one release and holds the buyer's configuration. Each buyer gets their own worker: sandbox, volume and broker token
Test environmentWhere you try a release before buyers do. Today the local kit (pigeonpost nest run); hosted test Nests come later

How a job flows#

  1. 1. A buyer invokes an operation on a listing, with a payload.
  2. 2. Admission checks that the release is approved and live and that the payload matches the operation's fields.
  3. 3. The job reaches the buyer's own worker as a file in its inbox.
  4. 4. Your app answers, calling the model broker if it needs a model.
  5. 5. The buyer gets your answer, sources and model_used, or your error_code.
