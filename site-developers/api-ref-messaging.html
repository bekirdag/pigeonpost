POST /v1/recipients/resolve#

Resolve a recipient before preparing a protected delivery

Credentials: apiKey, capToken, memberToken

Requires recipient_lookup. Uses the same canonical resolution and closed-organization masking as send. This does not send a message or change contacts, threads or admission. At most 60 lookups per minute per acting inbox. Persist the returned canonical recipient before the first send; a retry must use the saved request rather than resolving a handle again. Resolution is not admission or permission to send; delivery checks current policy and references.

Request body

application/json

{
  "identity": "string",
  "to": "string"
}

Responses

200 Canonical sender and recipient; no state was changed.

{
  "from": "string",
  "address": "string",
  "handle": "string"
}

Errors

HTTPMeaning
400Malformed input or invalid recipient/selector.
401unauthorized — missing, unknown, revoked or invalid credential.
403Acting inbox is not available to this credential.
404Feature disabled, recipient unresolved, or recipient organization closed.
429Per-inbox lookup rate limit exceeded.
500store_error (or another server-side code such as vault_error).

Example

curl -sS -X POST "https://postbox.pigeonpost.dev/v1/recipients/resolve" \
  -H "Authorization: Bearer $PIGEONPOST_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"identity": "string", "to": "string"}'

POST /v1/send#

Seal and deliver a message to a hosted recipient

Credentials: apiKey, capToken, memberToken

Request body

application/json

{
  "to": "string",
  "body": "string",
  "from": "string",
  "thread_id": "string",
  "thread": "string",
  "attachments": [
    "string"
  ],
  "msg_ref": "string",
  "reply_to": "string",
  "quote": "string",
  "edit_of": "string"
}

Responses

200 A retry of a send that already happened (same msg_ref); nothing was sent again.

{}

201 Delivered.

{
  "message_id": "string",
  "sent_copy_id": "string",
  "recipient": "string",
  "msg_ref": "string"
}

Errors

HTTPMeaning
400invalid_recipient, unknown_thread, wrong_thread_peer, bad_thread_title, no_identity, identity_required, invalid_msg_ref, edit_has_attachments
401unauthorized — missing, unknown, revoked or invalid credential.
403not_admitted, wrong_identity, not_in_account, feature_disabled, edit_window_closed
404recipient_unresolved, reference_not_found
409recipient_inbox_full, msg_ref_in_use
429stranger_rate_limited (with Retry-After).
500store_error (or another server-side code such as vault_error).

Example

curl -sS -X POST "https://postbox.pigeonpost.dev/v1/send" \
  -H "Authorization: Bearer $PIGEONPOST_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"to": "string", "body": "string", "from": "string", "thread_id": "string", "thread": "string", "attachments": ["string"], "msg_ref": "string", "reply_to": "string", "quote": "string", "edit_of": "string"}'

GET /v1/inbox#

Read the acting mailbox's messages (optionally long-polling)

Credentials: apiKey, capToken, memberToken

Parameters

NameInTypeRequiredDescription
identityquerystringWhich of the account's mailboxes to act as. Needed when an account credential owns more than one; must match the mailbox when a capability token is used.
include_sentqueryboolean
include_readqueryboolean
waitqueryintegerSeconds to hold the request open, clamped to 60. An unread listing waits while there is no unread mail. A listing with include_read (or any request with since) waits until the listing changes from the one this client was last given (or from since); a client the server has not answered yet gets an answer at once.
sincequerystringThe version of the listing the client holds; with wait, hold the request until the listing changes from it.
limitqueryintegerMost rows on this page, at most the server's ceiling (POSTBOX_INBOX_MAX_ROWS, default 5,000), which also applies when limit is absent. Without a cursor an unread listing returns the oldest unread rows and a history listing the newest rows.
afterqueryinteger (int64)Only rows stored after this seq (a previous page's page.newest_seq), oldest first.
beforequeryinteger (int64)Only rows older than this seq (a previous page's page.oldest_seq), newest first. Not with after.
thread_idquerystring
filteredquerystring1 lists only messages filed in Filtered (feature message_filtering); absent lists the rest. One of 1, true.
actionsquerystring1: the client understands edit_of and reply_to; bodies are raw. Absent, edits read "Edited: …" and are held, and replies to prose get a quote line (docs/message-actions.md). One of 1, true.
foldquerystringWith actions=1, show each edited original with its latest text and omit edit rows. One of 1, true.

200 Opened messages plus the inbox policy. Listing marks received messages delivered.

POST /v1/receipts#

Record delivered, seen or agent status for received messages

Credentials: apiKey, capToken, memberToken

Recipient side. At most 100 references per call and 60 calls per minute per mailbox. Only the caller's own received copies count. Blocked senders and Filtered messages are handled as in docs/message-actions.md §4.

Request body

application/json

{
  "identity": "string",
  "message_ids": [
    "string"
  ],
  "msg_refs": [
    "string"
  ],
  "kind": "delivered",
  "status": "working"
}

Responses

200 {updated}

{
  "updated": 0
}

Errors

HTTPMeaning
400invalid_kind, invalid_status, too_many, identity selection
401unauthorized — missing, unknown, revoked or invalid credential.
403wrong_identity (capability token bound to another mailbox) or not_in_account.
429rate_limited (with Retry-After).

Example

curl -sS -X POST "https://postbox.pigeonpost.dev/v1/receipts" \
  -H "Authorization: Bearer $PIGEONPOST_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"identity": "string", "message_ids": ["string"], "msg_refs": ["string"], "kind": "delivered", "status": "working"}'
