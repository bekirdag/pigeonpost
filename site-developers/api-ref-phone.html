SMS-verified phone numbers on mailboxes, opt-in discoverable (Phase 10, docs/contacts-and-phone.md).

MethodPathDoes
GET/v1/phoneThe account's verified numbers, masked (feature phone_numbers)
POST/v1/phone/verifyText a 6-digit code to a number for one of the person's mailboxes
POST/v1/phone/verify/{challenge_id}Prove the code and link the number
PATCH/v1/phone/{id}Turn discoverability on or off, or move the number to another own mailbox
DELETE/v1/phone/{id}Unlink a number (works with the flag off too)

Base URL https://postbox.pigeonpost.dev. Overview: HTTP API.

GET /v1/phone#

The account's verified numbers, masked (feature phone_numbers)

Credentials: memberToken

Responses

200 Numbers.

{
  "numbers": [
    {
      "id": "string",
      "identity": "string",
      "country_code": "string",
      "masked": "+90 ••• ••• ••12",
      "discoverable": false,
      "verified_at": 0
    }
  ],
  "max_numbers": 0
}

Errors

HTTPMeaning
401unauthorized — missing, unknown, revoked or invalid credential.
403human_required or credential_not_accepted — only a person signed in interactively (not an API key, mailbox token or connector).
404feature_disabled

Example

curl -sS "https://postbox.pigeonpost.dev/v1/phone" \
  -H "Authorization: Bearer $PIGEONPOST_TOKEN"

POST /v1/phone/verify#

Text a 6-digit code to a number for one of the person's mailboxes

Credentials: memberToken

The answer is the same for every acceptable number, whether or not it is on Pigeonpost. The code is valid for 10 minutes and 5 tries. Resend limits: 1 per 60 s and 5 per 24 h per number, 10 per 24 h and 3 pending per account, 20 per 24 h per IP, plus the platform SMS budget (docs/contacts-and-phone.md §4).

Request body

application/json

{
  "phone": "string",
  "identity": "string"
}

Responses

202 Code sent.

{
  "challenge_id": "string",
  "expires_at": 0,
  "resend_after": 0,
  "code_length": 0
}

Errors

HTTPMeaning
400invalid_phone, bad_request
401unauthorized — missing, unknown, revoked or invalid credential.
403human_required or credential_not_accepted — only a person signed in interactively (not an API key, mailbox token or connector).
404feature_disabled
409phone_limit (3 numbers per account)
422phone_not_supported (premium-rate, network or blocked prefix)
429rate_limited with Retry-After and limit (requests, ip, daily, monthly, resend, number, account, pending).
503sms_unavailable — the SMS provider is not configured or down, or a platform SMS budget is spent.

Example

curl -sS -X POST "https://postbox.pigeonpost.dev/v1/phone/verify" \
  -H "Authorization: Bearer $PIGEONPOST_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"phone": "string", "identity": "string"}'

POST /v1/phone/verify/{challenge_id}#

Prove the code and link the number

Credentials: memberToken

discoverable is false unless the person ticked "Let people who have my number find me". If another account had this number, it moves here and that account receives phone.unlinked {reason: verified_elsewhere}.

Parameters

NameInTypeRequiredDescription
challenge_idpathstringyes

Request body

application/json

{
  "code": "string",
  "discoverable": false
}

Responses

200 Linked.

{
  "number": {
    "id": "string",
    "identity": "string",
    "country_code": "string",
    "masked": "+90 ••• ••• ••12",
    "discoverable": false,
    "verified_at": 0
  }
}

Errors

HTTPMeaning
400invalid_code (with attempts_left), bad_request
401unauthorized — missing, unknown, revoked or invalid credential.
403human_required or credential_not_accepted — only a person signed in interactively (not an API key, mailbox token or connector).
404feature_disabled
409phone_limit
410challenge_expired (expired, used up, or not this account's)

Example

curl -sS -X POST "https://postbox.pigeonpost.dev/v1/phone/verify/$CHALLENGE_ID" \
  -H "Authorization: Bearer $PIGEONPOST_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"code": "string", "discoverable": false}'
