Find people I know by hashed phone number, and SMS invitations (Phase 10, docs/contacts-and-phone.md).

MethodPathDoes
POST/v1/contacts/discoverWhich hashed numbers belong to people who chose to be found (feature contact_discovery)
POST/v1/contacts/invitesInvite one contact by SMS, on the person's explicit tap (feature sms_invites)

Base URL https://postbox.pigeonpost.dev. Overview: HTTP API.

POST /v1/contacts/discover#

Which hashed numbers belong to people who chose to be found (feature contact_discovery)

Credentials: memberToken

Each hash is the first 16 bytes of SHA-256("pigeonpost:phone:v1:" || E.164) as 32 lowercase hex characters (docs/contacts-and-phone.md §3). Nothing of the upload is stored. Only verified, discoverable, existing mailboxes are returned, never the caller's own numbers or anyone who blocked one of the caller's mailboxes. A person only. Limits: 500 hashes per request, 20 requests per hour per account and 30 per IP, 1,000 new hashes per day (200 for accounts under a day old) and 5,000 per 30 days.

Request body

application/json

{
  "hashes": [
    "string"
  ]
}

Responses

200 Matches.

{
  "matches": [
    {
      "hash": "string",
      "address": "string",
      "handle": "string",
      "display_name": "string"
    }
  ],
  "checked": 0,
  "new": 0,
  "remaining_today": 0
}

Errors

HTTPMeaning
400bad_request
401unauthorized — missing, unknown, revoked or invalid credential.
403human_required, credential_not_accepted, discovery_locked (with until)
404feature_disabled
429rate_limited with Retry-After and limit (requests, ip, daily, monthly, resend, number, account, pending).
503discovery_busy (platform-wide circuit breaker, with Retry-After)

Example

curl -sS -X POST "https://postbox.pigeonpost.dev/v1/contacts/discover" \
  -H "Authorization: Bearer $PIGEONPOST_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"hashes": ["string"]}'

POST /v1/contacts/invites#

Invite one contact by SMS, on the person's explicit tap (feature sms_invites)

Credentials: memberToken

The sender must have a verified number. confirm must be true. Per sender: 5 a day, 20 per 30 days. Per receiving number (all senders): 1 per 7 days, 3 per 30 days; never after an opt-out. not_sent.reason is already_invited (you, within 30 days) or unavailable (deliberately merged: opted out, invited recently by others, or not supported).

Request body

application/json

{
  "phone": "string",
  "confirm": false,
  "identity": "string"
}

Responses

200 Sent or not.

{
  "status": "sent",
  "invite_id": "string",
  "reason": "already_invited"
}

Errors

HTTPMeaning
400confirm_required, invalid_phone, bad_request
401unauthorized — missing, unknown, revoked or invalid credential.
403human_required, credential_not_accepted, phone_required
404feature_disabled
429rate_limited with Retry-After and limit (requests, ip, daily, monthly, resend, number, account, pending).
503sms_unavailable — the SMS provider is not configured or down, or a platform SMS budget is spent.

Example

curl -sS -X POST "https://postbox.pigeonpost.dev/v1/contacts/invites" \
  -H "Authorization: Bearer $PIGEONPOST_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"phone": "string", "confirm": false, "identity": "string"}'

POST /v1/sms/opt-out#

Stop SMS invitations to the number an invitation code was texted to (public)

Credentials: none

Always answers {"ok": true}, so a code reveals nothing. Rate-limited per IP.

Request body

application/json

{
  "code": "string"
}

Responses

200 Done (or nothing to do).

{
  "ok": false
}

Errors

HTTPMeaning
429rate_limited

Example

curl -sS -X POST "https://postbox.pigeonpost.dev/v1/sms/opt-out" \
  -H "Content-Type: application/json" \
  -d '{"code": "string"}'
