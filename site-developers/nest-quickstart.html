Quick start

Pick a template#

List the starter templates:

TemplateDescription
toolA no-AI tool: summarizes a CSV table. No broker, no network.
docs-qaAI Q&A over documents bundled with the release, through the model broker. Based on the reference release hr-policy-qa.
approval-writeDrafts a helpdesk reply and posts it as an external write the buyer approves first.

Initialize the app#

Create a new app from the docs-qa template. --publisher is your publisher name, the first part of the listing address; add --lang python for Python.

This writes the following files:

FilePurpose
nest-release.tomlThe release manifest: what the release is and may do
operations/docs.ask.jsonThe operation descriptor
jobs/example.jsonA job to run locally
README.mdThe template's notes
app.mjsThe app
app.test.mjsIts unit tests
ContainerfileThe image assembly: one base pinned by digest, then file copies (no RUN)
pigeonpost-nest.mjsThe SDK (Node ESM, no dependencies)
docs/handbook.mdThe bundled documents (synthetic sample text; replace it)

A Python app also gets nest-build.toml, the compile step that installs its pinned wheels offline before the image is assembled (how a release is built).

Test the approval flow#

The approval-write template posts a reply to the buyer's helpdesk, an external write the buyer approves first:

The first delivery ends with approval_required and the effect waits. --approve-all approves it as the buyer would and delivers the job again with the same id: the effect is performed once. --redeliver then delivers it a third time, as the platform may: the effect has the same idempotency key, so it is reported as already done and nothing is posted twice.

External writes are not offered at launch; review blocks external_writes = true until they are. The flow runs in the local kit now.

Options for nest run#

OptionWhat it does
--job FILEA job file; repeatable. Default jobs/example.json
--config FILEThe installation's configuration, checked against the manifest's config_schema with defaults filled in
--reply TEXTThe mock model's reply; repeat for successive requests
--no-modelThe broker answers no_model
--approve KEYApprove the effect with this key; the job is delivered again with the same id
--approve-allApprove every effect the app asks for
--redeliverDeliver each job once more after it finishes
--timeout SECSSeconds to wait for each result; default 30
--keepKeep the emulated volume and print where it is
--jsonA machine-readable report (pigeonpost --json nest run …)
-- <command>How to start the app; default node app.mjs or python3 app.py
