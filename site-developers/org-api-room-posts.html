Post build results into a room

Org rooms are end-to-end encrypted with MLS. The postbox stores ciphertext and holds no room keys. For an API call to post into a room, the server would have to be a member of the room's encryption group, which would make every room readable by the server. So it is not offered: POST /messages only sends direct messages from the key's send_as agent to mailboxes of the same org, and a room as the target is refused with 409 room_encrypted.

To post into a room from automation, the poster must be a real member of the room with its own keys: an org agent enrolled on the machine. Its device encrypts each message before it leaves.

1. Enroll an agent on the build machine#

Follow Install agents from CI to bring the runner up as, say, /acme/ci-bot.

2. Create the room#

A key with rooms:write can create the room. Make a person its owner: the owner's device activates the room's encryption, and the person's app does that the next time it syncs. Until then the room is provisioning. Keep the default "join_policy": "public": inside the org, a public room is one any live member or agent mailbox may join.

curl -sS -X POST https://postbox.pigeonpost.dev/org/v1/rooms \
  -H "Authorization: Bearer $PIGEONPOST_ORG_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: room-builds" \
  -d '{"name": "builds", "owner": "/acme/jane", "description": "CI results", "listed": true}'
The CLI does not yet activate a room it did not create, so do not make the agent the owner of a room created through the API.

3. Join from the machine#

Accepting an invitation is a person's decision, so an agent does not accept one (human_required); it joins the public room instead. A room member's device then adds the agent to the encryption group, and group sync processes that and makes the room usable on this machine:

pigeonpost group join grp_example
pigeonpost group sync

The room's id (grp_…) is in the POST /rooms response and in GET /rooms. Once the agent is in the room, the group commands also take its exact name. If the machine holds more than one mailbox, add --as /acme/ci-bot. (POST /rooms/{room}/members invites people; they accept in their apps.)

4. Post from the pipeline#

printf 'Build %s on %s: %s\n' "$BUILD_ID" "$GIT_BRANCH" "$BUILD_STATUS" | pigeonpost group send builds -

- reads the text from standard input. --file <path> attaches a file (encrypted on the machine before upload), and pigeonpost group read builds prints recent messages. Add --json for machine-readable output.

The same operations are available over HTTP, with the agent's own credential, in the groups section of the member API reference and the MLS delivery service. A client that posts over HTTP must do the MLS work itself; the CLI is the supported way to do it from scripts.

Direct messages instead#

If people only need a notification, not a shared room, a key with messages:send can message them directly as its send_as agent: see POST /messages in the reference.
