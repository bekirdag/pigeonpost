# Pigeonpost for Android

Native Kotlin and Jetpack Compose client for Pigeonpost, published by Wodo Teknoloji A.Ş. The iOS app under `apps/ios` is the page/workflow reference. The client uses the production API, browser sign-in and Google Play handle subscriptions.

## Build

Use JDK 17 and an Android SDK with `platforms;android-36` and `build-tools;35.0.0`. Open this directory in Android Studio, or set `ANDROID_HOME` / an ignored `local.properties` containing `sdk.dir=/absolute/path/to/sdk`.

```sh
./gradlew :core:test :app:lintDebug :app:assembleDebug :app:assembleRelease :app:bundleRelease
./gradlew :app:connectedDebugAndroidTest
```

The second command needs a connected device or emulator. The wrapper pins Gradle 8.13 and verifies its distribution SHA-256. AGP 8.13.2, Kotlin 2.2.21 and Compose BOM 2025.12.01 are pinned as a compatible API 36 toolchain; dependency upgrade notices are reviewed separately from build failures.

- Installable development APK: `app/build/outputs/apk/debug/app-debug.apk` (`dev.pigeonpost.inbox.debug`, Android debug signing).
- Unsigned release APK: `app/build/outputs/apk/release/app-release-unsigned.apk`.
- Release bundle: `app/build/outputs/bundle/release/app-release.aab` (unsigned unless an upload key is supplied).
- Minimum Android version: Android 8.0 / API 26. Compile and target: API 36.
- GitHub Actions: [Android workflow](../../.github/workflows/android.yml) builds these artifacts and runs JVM and emulator tests. CI validates and produces artifacts; Play releases require the dedicated upload key and a separate console submission.

## Implemented workflows

Browser sign-in with PKCE and provider selection; first-inbox creation; mailbox switching; inbox/search/unread/held states; conversation subjects; message history, send and acknowledgement; native Markdown, find, copy and original text; delete/report messages; document/photo attachments and Android open/share/save; contacts with namespace precedence and explicit permission confirmation; archive; quota; free handle registration for approved testers; up to ten annual Google Play handle subscriptions with restoration; versioned terms acceptance; policy/support links; account deletion requests; account sign-out; QR sign-in scanning directly in Settings; background notifications through Firebase Cloud Messaging; phone layout and the iPad/desktop three-column layout on tablets, foldables and landscape windows; System/Light/Dark appearance choice; voice and video calls; in-app attachment viewer; adaptive and themed Pigeonpost launcher icons.

### Privacy, calls and groups (0.4.0, Phases 1b and 3b)

Everything here is gated on `GET /v1/capabilities`; with a feature off the app looks as before.

- **Calls page** (`call_history`): a Calls tab beside Conversations on phones, a Calls row under the mailbox switcher on tablets, with the unseen-missed badge (cleared when viewed). All · Missed, call back, delete, block, report, clear all, and a collapsed Filtered calls section. Incoming missed one-to-one calls appear as a line in the open conversation.
- **Filtering** (`message_filtering`, `call_admission`): a Filtered (n) row at the end of the list opens the senders the server filtered; each offers Accept (contact + move to inbox), Block (report on) and per-message Report. Settings → Privacy & filtering holds the six controls; Settings → Blocked lists exact and wildcard blocks with Unblock and a field to add one.
- **Blocking**: one confirmation sheet ("They won't be able to message or call you, and won't be told.", Also report as spam, Block everyone at /ns) from the conversation menu, conversation info, the message menu, call rows, group members and Filtered. A blocked conversation shows a banner with Unblock instead of the composer; group messages from a blocked person are hidden behind "Show".
- **Profile pictures** (`avatars`): Settings → Profile picture: photo picker or camera, a square crop with zoom done on the device (re-encoded as JPEG, nothing of the original file is uploaded), Everyone / People I know / Nobody, Use for all my mailboxes, Remove. Pictures replace initials wherever a face is drawn (`Avatar` reads `LocalAvatars`) and the sender's last-seen picture is the notification's `Person` icon (read from the app's cache, never fetched by the push).
- **Disappearing messages** (`disappearing`): direct-subject timers in conversation info, a timer badge in the bar and on each message, and local expiry on the device's own clock (`InboxStore.pruneExpired`, scheduled at the next `expires_at`).
- **Groups** (`groups`, docs/groups.md): pending invitations and groups at the top of the conversation list; New group from the compose menu (phones) or the sidebar (tablets); the group view with sender names and faces, notices from verified commits ("Jane added a new device" with its fingerprint; security warnings when a commit or sender does not verify), announcement bar, encrypted attachments (sealed and uploaded on send, fetched and decrypted into private cache to view), group voice/video calls through the call page (`PigeonpostCalls.placeGroup/joinGroup`) and "Call in progress — Join"; group info with members, roles, add people, invite link (shown once), settings, timer, notifications, safety number and per-member device fingerprints; leave, transfer and delete. Settings → Group encryption shows this device's fingerprint and removes the device. Invite links `https://inbox.pigeonpost.dev/g/<id>#token` open the app (App Link, verified by `site-inbox/.well-known/assetlinks.json`) and show a preview before joining.
- **Group encryption library.** `crates/pigeonpost-groupcrypto` built as an AAR (arm64-v8a, armeabi-v7a, x86_64, 16 KB aligned) by `scripts/build-android.sh`; the app depends on `crates/pigeonpost-groupcrypto/target/android/pigeonpost-groupcrypto.aar` and JNA 5.17.0, and the build stops with instructions when the AAR is missing (`eval "$(crates/pigeonpost-groupcrypto/scripts/fetch-kotlin-tools.sh /tmp/kotlin)"; ANDROID_NDK_HOME=… crates/pigeonpost-groupcrypto/scripts/build-android.sh`). The client loop (`core/groups/GroupClient.kt`) is the web inbox's `groups-core.js` in Kotlin: device registration with the postbox's attestation, ≥ 10 key packages plus a last-resort package, Welcomes, strict in-order processing, pending adds and removals with jittered commits and conflict retry, epoch conflicts re-encrypted under the same client message id, and the state blob persisted after every mutating call. State at rest (`KeystoreGroupStorage`): one file per mailbox in no-backup storage, AES-256-GCM under an Android Keystore key with the mailbox as AAD; the library's own state key and the decrypted history are inside it. Clearing app data destroys the device; it is re-enrolled and re-added without history. R8 keeps `dev.pigeonpost.groupcrypto.**` and `com.sun.jna.**`.
- **Tests.** Core JVM tests run the client loop against real MLS: `cargo build --release -p pigeonpost-groupcrypto-ffi` in the crate makes the host library, and `GROUPCRYPTO_REQUIRED=1` (set in CI) fails instead of skipping without it. The `safety` and `groups` fixtures drive the new screens; the groups fixture runs the real AAR for the app and two other people on an in-memory postbox (`core/src/groupcrypto-fake`). `LocalPostboxMlsTest` is an on-device round trip against a real local postbox: `node tests/e2e-groups/android-postbox.mjs`, `adb reverse tcp:18555 tcp:18555`, push the JSON line it prints to `/sdcard/Android/data/dev.pigeonpost.inbox.debug/files/postbox.json`, then run the class.

### Live streams and meeting notes (0.4.1, Phases 6 and 7)

- **Live streams in groups** (`streaming`, docs/streaming.md). The group view shows a red **LIVE** banner ("Jane is live: Sprint demo — Watch"), read from `GET /v1/groups/{id}/streams` while the group is open. Watch, and Go live (camera and microphone; Android's WebView cannot share its screen), run in the call page through `PigeonpostNative.watchStream`/`goLive` (`calls/CallHost.kt`); the media, the stream key and the stage stay in `live.js`. Go live is offered only to members the group's `stream_policy` allows (admins, or everyone; never restricted members) and asks for the camera and microphone first. Group info has "Who can go live" for admins. While a stream is on screen the app rereads `GET /v1/streams/{id}` every few seconds and tells the page what only the postbox knows (`PigeonpostLive.onGroupStream`): a stage invitation (the page offers the stage; nothing opens until the person joins), being taken off the stage, and the end — what `groups.js` gets from `group.stream` events on the web. The banner says when you are invited. Ended streams post the `stream` notice ("Jane streamed for 34 min · 18 viewers").
- **Audio focus and the foreground service** (`calls/LiveMedia.kt`). While a stream is shown the app holds media audio focus; losing it (another app, a phone call) mutes the stream's players until focus returns. A `LiveStreamService` foreground service (type `mediaPlayback`, plus `camera|microphone` for the streamer and stage speakers when those permissions are held) keeps the stream going in the background, with Leave/End stream in its notification. It starts only from a tap on Watch or Go live, and stops when the page no longer shows a stream.
- **Meeting notes** (`meeting_summaries`, docs/meeting-summaries.md). Settings → Meeting notes (and a sidebar row on tablets) lists the meetings whose notes this account agreed to and opens a brief on the device: summary, decisions, action items, open questions and transcript, Copy as text, Delete my copy. The brief is decrypted here with this device's notes key (`meetings/KeystoreNotesKey.kt`): on Android 12+ a P-256 key made inside the Android Keystore for key agreement only; on Android 8–11 a P-256 key whose PKCS#8 bytes are kept only as AES-GCM ciphertext under a Keystore key in no-backup storage. The key is registered for the account while the feature is on (as the web inbox does), so notes made from then on open here; signing out destroys it. Consent, the notes indicator and capture stay in the call page (`calls-summary.js`).
- **Tests.** JVM: stream models, policy, banner/stage wording and page events; the meeting-notes cryptography against a brief sealed by meeting-intel's own `sealBrief` (`core/src/test/resources/meeting-notes-vector.json`), tampering, wrong keys and the store. Emulator (phone and tablet): `LiveStreamsUiTest` (banner, stage invitation, end, policy, the WebView bridge with a loopback page, the foreground service), `MeetingNotesUiTest` (Keystore key registered, brief sealed for it by the `live` fixture and opened, other devices' notes, failures, delete), `NotesKeystoreTest` (both key paths), and `tests/e2e-streams/android-app.mjs` + `LiveStreamE2eTest` (the app watching a real end-to-end encrypted stream through the real page, local LiveKit, synthetic media).

### Incoming calls on the lock screen (Phase 1c)

A call reaches the phone with the app closed, in the background or behind the lock screen (`docs/call-alerting.md`). The postbox sends an FCM data message `type=call_ring` (room, ring token, caller, expiry); `push/PigeonpostMessagingService.kt` routes call messages before mail. `core/CallRings.kt` accepts a ring only for the signed-in push mailbox, with a well-formed room (`[A-Za-z0-9_-]{10,64}`), ring token (`[A-Za-z0-9_-]{43}`), addresses and kind, not past `expires_at` (nor more than 3 minutes ahead); display names lose control and bidi characters and are cut to 60 characters. `calls/IncomingCalls.kt` posts a `NotificationCompat.CallStyle.forIncomingCall` notification on the `calls` channel (high importance, the ringtone with ringtone audio attributes, vibration, `CATEGORY_CALL`, public on the lock screen, insistent so it rings until it goes, timing out at the ring's expiry) with a full-screen intent to `calls/IncomingCallActivity.kt`: over the lock screen, screen on, caller avatar, name and handle, Answer and Decline. Answer opens the app (behind a PIN the person unlocks first) and the call page accepts with `PigeonpostNative.answer(room, ringToken)` once signed in; Decline posts `/calls/v1/rings/{room}/decline` with the ring token from a receiver, with no member token. The ring is taken down (which stops the ringtone) by `call_cancel`, the page's `ring_ended`, the expiry, a decline, sign-out, or the incoming screen's poll of `GET /calls/v1/rings/{room}` every 2.5 s. With the app on screen nothing is posted and the page's own ring screen answers; off screen the page is configured with `nativeRing: true` and its `ring` messages raise the same notification (one per room, merged with the push). On Android 14+ the app asks once, and Settings › Inbox and storage keeps a button, to allow full-screen notifications (`ACTION_MANAGE_APP_USE_FULL_SCREEN_INTENT`); without it calls still ring as a heads-up notification.

Not used: `androidx.core.telecom`/a self-managed `ConnectionService`. The call's audio is Chromium's inside the WebView, so Telecom would own audio routing it cannot actually route, and it needs a `phoneCall`/`microphone` foreground service for the whole call; the notification and full-screen screen give the same lock-screen experience with less risk. A force-stopped app (Settings › Force stop) receives no FCM until opened again, as with any app.

Debug builds take an FCM-shaped test push over adb (`DebugPushReceiver`, adb shell only): `adb shell am broadcast -n dev.pigeonpost.inbox.debug/dev.pigeonpost.inbox.DebugPushReceiver -a dev.pigeonpost.inbox.debug.PUSH -f 0x20 --es type call_ring --es room … --es ring_token … …`. A launch with the call harness extras is remembered, so a test that kills the app first still rings for the harness mailbox and answering reopens into the harness.

### Design, tablet layout and calls (0.3.0)

- **Design.** Colours, type and shapes follow the conversation design token for token with the iOS `Theme.swift` (dark exact, light matched): Geist and Geist Mono are bundled from `apps/ios/Shared/Fonts` (SIL OFL 1.1, `app/src/main/assets/Geist-OFL.txt`), messages are cards with a decision header and a copy/time/actions footer, faces use the web/iOS tone hash (`core/PeerFace.kt`). Settings → Appearance chooses System, Light or Dark; the choice is kept on the device (it is not cleared by sign-out).
- **Tablet layout.** Windows at least 700 dp wide get three columns, modelled on `apps/ios/Shared/Views/Desktop/DesktopInboxView.swift`: conversations with the mailbox switcher (an in-column list with copy buttons), the subjects ("Threads") of the open conversation, and the thread. "Hide conversations" in the column's bar folds the first two columns away; "Show conversations" in the thread's bar (or the empty pane) always brings them back. Phones keep the single-pane flow.
- **Messages.** Message text is one selection: long-press selects part of a message and copies it; the long-press menu lives on the card's header and footer bands and the ⋯ button. After Send the composer keeps focus and the keyboard (the field is read-only, not disabled, while a message is sending).
- **Attachments.** Images, video, audio, PDF and plain text (`text/plain`, CSV, Markdown and JSON shown as text) open in an in-app viewer with a download button; `core/AttachmentKinds.kt` decides, and HTML, SVG and XML never render. Download saves photos and videos to the gallery (`Pictures/Pigeonpost`, `Movies/Pigeonpost`, Android 10 and later, no storage permission) and other files through the system save dialog. The file menu keeps Open, Share and Save a copy.
- **Calls.** As on iOS (`apps/ios/Shared/Calls/CallHost.swift`), calls are the web client (`site-inbox/calls.js`) in a WebView that loads `https://inbox.pigeonpost.dev/native-call.html` once while signed in and stays loaded, invisible and untouchable, so an incoming call rings while the app is open (`calls/CallHost.kt`, `calls/CallFrame.kt`). The page talks to the app through the `PigeonpostAndroid` JavaScript interface (`ready`, `mode`, `renew`, `toast`); the app calls `PigeonpostNative.configure/renewed/call/signOut`. Mode `full` covers the screen inside the system bars, `mini` is a 64 dp strip at the top with the app pushed down, `hidden` lets every touch through. The screen stays awake while a call shows. Microphone and camera are granted only to the page's origin, after the app holds `RECORD_AUDIO`/`CAMERA` (asked when a call starts or is answered); navigation is pinned to the page and other links open in the browser. Voice and video buttons sit in the conversation bar and are disabled while a call is showing. Ringing while the app is closed or the phone is locked is Phase 1c, below. Not covered: sending this device's screen (Android WebView has no `getDisplayMedia`); others' shared screens are shown. The page is served live, so web deploys change Android calls too.

Settings follows the iOS handle flow: enter a name, check availability, confirm registration, then open the new `/name/main` inbox. Approved testers retain one complimentary handle, authorized by the server's private allowlist. The separate paid section uses Google Play Billing 9.1.0 and server verification for up to ten annual subscriptions. The app displays Google's localized prices and renewal terms before checkout. See the [billing setup and validation guide](BILLING.md) and [complimentary handle configuration](../../deploy/postbox/README.md#complimentary-preview-handles). Play internal-test membership, license testing, and complimentary-handle eligibility are separate settings.

`core` owns wire models, conversation/subject assembly, the API client and coroutine state. `app` owns Compose, Android lifecycle, AppAuth, Keystore, file pickers/FileProvider and QR capture. HTTP, response decoding and Markdown parsing run off the UI thread. History always requests both sent and read messages. Drafts are isolated by mailbox, peer and subject and live for the view model's lifetime; they are cleared by sign-out and are not restored after process death. A failed or uncertain send is never automatically repeated.

Conversation rendering starts with the latest ten messages in a native reverse-layout lazy list. Scrolling toward older history adds ten at a time; search can reveal matches outside that window. The REST response remains a complete snapshot. Stable message IDs preserve a reader's position when messages arrive, and saved window boundaries and a viewport anchor preserve it through screen recreation. The latest message stays bottom-aligned even when taller than the screen or resized by delayed content and the keyboard.

The inbox front page has no duplicate address strip. Copy controls remain in the mailbox picker and Settings. The picker keeps the account's main readable root first, followed by other purchased roots, named children and raw key addresses. Get a handle contains new-registration and paid-but-unassigned recovery controls; existing names remain under Handles, with Google Play renewals, restore and management in their own subpage.

The app uses the existing public client `pigeonpost-mobile`, issuer `https://auth.pigeonpost.dev/realms/pigeonpost-prod`, and callback `dev.pigeonpost.inbox://oauth2redirect`. It has no client secret. AppAuth request state/PKCE are persisted with the session in app-private, no-backup storage encrypted by an Android Keystore AES-GCM key. Do not install debug and release builds together when testing authentication: both deliberately use the existing registered native callback scheme.

Message bodies are presentation data. Server `autonomy`, `verb` and `held_because` decide the displayed state. Opening a subject marks its incoming messages read; it does not authorize agent execution. Contact permission options come from the server vocabulary and exclude `never_auto`. Adding a known sender grants no new automatic permissions.

## Repeatable UI checks

Ordinary debug launches use the real service. The explicit debug-only fixture path supports deterministic instrumentation and screenshots:

```sh
adb shell am start -S -n dev.pigeonpost.inbox.debug/dev.pigeonpost.inbox.MainActivity \
  --es pigeonpost.fixtures inbox
```

Modes: `policy` (terms acceptance), `inbox`, `safety` (Phase 1b features on: calls, filtered mail, a picture, timers), `groups` (real group encryption with Bob and Carol on an in-memory postbox), `empty`, `offline`, `signin`, `long` (1,000 historical messages), `long-tall` (also an oversized latest Markdown message), `handles` (approved tester registration), `store` (the invented fleet used for store screenshots). Add `--es pigeonpost.appearance dark|light` to pin the appearance without changing the saved choice.

Play screenshots come from the `store` fixture through `StoreScreenshots` (skipped unless asked for): `./gradlew :app:connectedDebugAndroidTest -Pandroid.injected.androidTest.leaveApksInstalledAfterRun=true -Pandroid.testInstrumentationRunnerArguments.class=dev.pigeonpost.inbox.StoreScreenshots -Pandroid.testInstrumentationRunnerArguments.storeShots=<name> [-Pandroid.testInstrumentationRunnerArguments.looks=dark,light]`, then `adb pull /sdcard/Android/data/dev.pigeonpost.inbox.debug/files/store/<name>`. See [store/README.md](store/README.md#screenshots).

Calls can be tested against the local call harness (a stand-in postbox, `calls-service` and a static server that injects synthetic microphones and cameras; never the computer's real devices). Debug builds only accept `--es pigeonpost.calls.page http://127.0.0.1:8460/native-call.html --es pigeonpost.calls.token tok-alice --es pigeonpost.calls.mailbox /k/alice… [--es pigeonpost.calls.handle /alice] [--es pigeonpost.call /bob:audio|video]` (after `adb reverse tcp:8460 tcp:8460`), allow cleartext only to `127.0.0.1`/`10.0.2.2`, and enable WebView remote debugging so the page's `PigeonpostCalls.inspect()` can be read over `adb forward … localabstract:webview_devtools_remote_<pid>`. The release source set has none of this. Start the emulator with `-no-audio -camera-front none`; receiving video needs `-gpu host` (the headless default's goldfish H.264 decoder drops every frame). Fixture classes live only in `src/debug`; the release source set contains a no-op hook. Fixture tests do not prove a real authenticated send, registration or notification was delivered.

## Release signing and service work

`dev.pigeonpost.inbox` is registered as Pigeonpost in Wodo's company Google Play account, with Play App Signing enabled. Keep Google's distribution signing key separate from the dedicated upload key. The iOS/Windows registrations are separate from this Android package.

The release build accepts these environment variables together: `ANDROID_UPLOAD_KEYSTORE` (absolute file path), `ANDROID_UPLOAD_STORE_PASSWORD`, `ANDROID_UPLOAD_KEY_ALIAS`, and `ANDROID_UPLOAD_KEY_PASSWORD`. Keep the upload key and passwords in an appropriate secret store. A signed release additionally requires `PIGEONPOST_FIREBASE_API_KEY`. Store the restricted Firebase client key outside Git and supply it through the local build environment or GitHub Actions secret of that name. Only non-secret Firebase project identifiers are tracked. Providing incomplete signing settings or omitting the Firebase key fails a signed build; unsigned development artifacts can use fixtures without a key. The dedicated upload key is stored outside the repository and its password is in macOS Keychain. No signing key is committed, and CI does not publish to Google Play.

## Release validation and limits

Android 0.4.2 (14) is the first Google Play upload since 0.3.0 (11) and carries 0.4.0 and 0.4.1 with it (0.4.0 (12) and 0.4.1 (13) were built but never uploaded): privacy and call admission, groups with end-to-end encryption, incoming calls on the lock screen, group live streams and the meeting notes reader. New since 0.4.1: a full-screen call on a phone held sideways paints its dark ground on all four sides, so the inbox no longer shows through as a white strip beside the display cutout and navigation bar.

Android 0.3.0 (11) brings the 19 October web/iOS work to Android: the conversation-design restyle with bundled Geist, the tablet three-column layout with hide/show controls, partial text selection, a System/Light/Dark choice, a composer that keeps focus after Send, the in-app attachment viewer, and voice/video calls through the shared web call client. Validation: JVM tests (including viewer type gating and the tone hash), lint, release R8 build with the upload key, and all 40 emulator workflow tests on API 34 (new: theme persistence across recreation, composer focus after Send, long-press selection versus the actions menu, the text viewer, and on a forced 1280×800 window the sidebar hide/show and in-column mailbox switching; the tablet tests also passed on a Pixel Tablet emulator). Calls were tested on the emulator against the local harness and a headless Chrome peer: outgoing audio and incoming video both connected directly with matching security codes and two-way audio (about 125 kbit/s each way), video decoded at 1080p/29 fps on the phone and 960×540 in the browser, the incoming ring, the system permission prompts, the 64 dp minimised strip with touches reaching the app beneath it, hang-up from the strip, and the call page surviving rotation. Not yet done on a physical device: a real call over mobile networks and the relay, Bluetooth/headset audio routing, and TalkBack over the call page.

Android 0.2.6 (9) brings the iOS build 41 inbox, mailbox-ordering, handle-acquisition and history fixes to Android. Release submission and signature evidence are recorded separately after the signed bundle is verified. On 15 September, Play showed the preceding 0.2.5 (8) publicly available at 100%, all 177 selectable territories targeted (including France), and one active base plan for each of the ten handle products.

Android 0.2.5 (8) adds recovery for interrupted handle requests, namespace labels for default inboxes, an automatic address slash, root Settings scanning and background notifications. The signed release was submitted for public Google Play review on 14 September 2026 with updated notification disclosures, store text and reviewer instructions. The console confirms all three publishing changes are in review, with no unsent changes; managed publishing is disabled, so approval releases the update at 100 percent in all selected countries. The app also requires a terms acceptance screen before messaging. The current terms revision is saved with the encrypted session; a fresh sign-in, a changed terms revision or sign-out requires acceptance again. Policy, support and account deletion links remain available before acceptance. Received messages can be reported from their actions menu, and senders can be blocked from Conversation info.

The reliability changes passed JVM tests, release lint/build/signature verification, all 18 existing emulator workflow tests, two notification privacy/account tests and an opt-in live FCM delivery test. After rotating the Firebase client key, the signed bundle was rebuilt and live FCM delivery passed again. Its SHA-256 is `e962b1ac503b0968f49868c4da85f56c744af48ee6662697acc9c0bcba9e6b2e`, built from `fa6f8888bbaddd20a0e4823a6e063f5c66ba873d`; [Android CI](https://github.com/bekirdag/pigeonpost/actions/runs/34844292101) passed at that commit. The consent screen was also checked at normal and 200% font scale. The preceding Play-installed 0.2.0 (3) passed real no-charge license-test purchases, server receipt verification, restoration and cancellation; see [billing validation](BILLING.md#validation). Fixture tests do not replace live service or device acceptance.

The old Firebase client key was revoked and verified rejected by Google; GitHub secret-scanning alert #1 is resolved. The replacement permits only Firebase Installations and FCM Registration, with Android restrictions for the production package's three current Play signing certificates and the separate debug package/certificate. All three production signing identities passed provider verification, and an unrelated package was rejected. Recheck these restrictions when Play signing certificates change. Build-time injection keeps the literal out of source; the key remains extractable from the app, so API/application restrictions and server authentication are still required.

Android notifications require device permission and notify the selected inbox. Foreground conversations continue to use bounded long polling. Push registration uses WorkManager and is revoked on sign-out; display is also gated locally by the selected identity. Google receives generic alerts and routing identifiers, without message text or attachments. Firebase Analytics is disabled. Physical-device QR camera, TalkBack, low-memory recovery, a French billing account and the remaining accelerated billing lifecycle cases still need wider device acceptance. Recheck Play policy declarations, reviewer credentials, public deletion/privacy URLs and product availability for every public release.
